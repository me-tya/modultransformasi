# Modul Transformasi IIS / SQL Express — STAGING, NOT production
Build on a connected machine (GitHub Actions). The server itself needs no internet to run. Use an IIS site at the root URL (not a virtual subdirectory), internal HTTPS certificate, ASP.NET Core Module / .NET 8 Hosting Bundle installed from an offline installer, and SQL Server Express. The app publish is self-contained win-x64 but IIS still needs ANCM. Install and patch prerequisites before isolation.
1. Create DB using schema.sql with an administrator account. Set app pool No Managed Code, dedicated identity, SQL integrated login and only SELECT/INSERT/UPDATE/DELETE permissions on Documents/Credentials. Do not use sa. Give Modify on attachment folder outside site; deny users direct folder access.
2. Set appsettings.json SQL instance and folder. Configure IIS HTTPS and offline certificate chain, Windows firewall deny external egress. No password/connection secret in browser. Validate SQL TLS certificate for production (TrustServerCertificate default is staging only).
3. Export Backup All JSON including attachments from live legacy app on an authorized connected workstation; transfer via approved encrypted internal media. Run import-backup.ps1 against EMPTY database with same folder path and appropriate identity. No data is included in GitHub artifact. Audit counts. Set passwords individually on server: MT.exe set-password user@kemenkeu.go.id. No demo password; use 12+ characters. Never transfer Firebase passwords.
4. Point IIS site physical path to published folder. No directory browsing. Keep app pool single worker. Configure protected persisted Data Protection keys and access logs before use.
5. Validate login/roles, WBS, all PM/CM operations, upload/preview, reports/PDF/Excel/PPT/OCR and Backup All with internet physically disabled. Check DevTools network. External links remain references and are not imported. Automatic Dashboard CM cloud sync and AI cloud generation disabled; embedded Dashboard CM iframe not yet ported. The legacy JS adapter is transitional, initial snapshots only, no live updates. Reload for other users' changes; optimistic row version conflicts require reload. Additional localStorage-based state and all embedded modules must still be audited. File garbage collection, comprehensive authorization for attachment access, restore, scalable backup and real SQL/IIS integration tests are not complete. Do not use production records until those items are resolved.
6. Back up SQL database and attachment directory together while writes are stopped, store encrypted on separate internal disk. JSON backup is application-data export, not a complete SQL disaster-recovery backup. SQL Express has 10 GB per database limit. Server folder storage reduces DB usage.
